APIs Ativas & Operacionais
O que é e Por Que Usar a API do GPS Paraíba?

Uma **API (Interface de Programação de Aplicações)** é uma ponte digital que permite que outros sistemas (como o seu site de vendas, formulários de WhatsApp, gateways de pagamento ou CRMs externos) conversem diretamente com o ERP da GPS Paraíba sem precisar de intervenção manual.

Verbo GET (Consultar Dados)

Usado para buscar/ler informações salvas no ERP. Exemplo: Seu CRM externo consulta quantas vendas foram realizadas hoje ou quais mensalidades estão pendentes.

Verbo POST (Cadastrar Dados)

Usado para enviar e salvar novos dados no ERP. Exemplo: Quando um cliente preenche um formulário de contratação no site, o site dispara um `POST` e o contrato já aparece pronto no painel.

Autenticação Padrão RFC 6750 (Bearer Token)
1. Bearer Token (Padrão)
Envie o cabeçalho padrão Authorization: Bearer <token> em cada chamada.
2. Formato Padrão JSON
Todas as respostas da API usam a estrutura leve e universal JSON UTF-8.
3. Códigos HTTP
200 OK (sucesso), 201 Created (criado), 400 (dados inválidos) e 401 (sem permissão).
Endpoint 1: Gestão de Vendas & Contratos
GET POST
URL Completa do Endpoint: https://gpsparaiba.com.br/api/v1/integracoes/vendas
Parâmetros de Consulta (Query Parameters para GET):
ParâmetroTipoExemploDescrição
limitInteger?limit=10Limita a quantidade de vendas retornadas (ex: 10 mais recentes).
statusString?status=AtivoFiltra por status da venda (ex: Ativo, Pendente, Cancelado).
qString?q=MariaBusca por nome do cliente, placa do veículo ou número do contrato.
start_dateData (YYYY-MM-DD)?start_date=2026-08-01Data inicial de ativação do contrato.
end_dateData (YYYY-MM-DD)?end_date=2026-08-31Data final de ativação do contrato.
seller_nameString?seller_name=FernandoFiltra vendas associadas a um vendedor específico.
Modelo do Payload de Envio (POST JSON): 
{
  "contract_number": "CTR-8840",
  "client_name": "Maria Oliveira",
  "ddd": "83",
  "contact": "998877665",
  "vehicle_type": "Carro",
  "vehicle_brand": "Toyota",
  "vehicle_model": "Corolla",
  "plate": "QFB-2026",
  "plan_name": "GPS Total",
  "monthly_fee": 79.90,
  "seller_name": "Vendedor Web",
  "instalacao": true,
  "status": "Ativo"
}
Exemplo em cURL com Bearer Token: 
curl -X POST https://gpsparaiba.com.br/api/v1/integracoes/vendas \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer gps_live_key_paraiba_2026" \
  -d '{
    "client_name": "Maria Oliveira",
    "contact": "998877665",
    "monthly_fee": 79.90
  }'

Autenticação por Bearer Token (Padrão RFC 6750)

Recomendamos utilizar o padrão mundial de mercado Authorization: Bearer <token> para integrar seus sistemas com máxima compatibilidade.

Token de API copiado para a área de transferência!
Como Enviar o Token nas Requisições:

Envie no cabeçalho HTTP (*Header*) de todas as suas chamadas:

Authorization: Bearer gps_live_key_paraiba_2026 *(Nota: O sistema também aceita o cabeçalho X-API-Key: gps_live_key_paraiba_2026 ou o parâmetro na URL ?api_key=... por compatibilidade).*
Recomendação de Segurança:
Mantenha seu Bearer Token protegido. Nunca compartilhe a chave de produção em código-fonte público ou scripts expostos no navegador.
